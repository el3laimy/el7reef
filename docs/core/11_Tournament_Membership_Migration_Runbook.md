# Runbook ترحيل عضويات منظمي البطولات — UCP-103

**الحالة:** التنفيذ المحلي والمحاكي والمعاينة المستهدفة مكتملة؛ التطبيق ينتظر backup وبيانات اعتماد كتابة مخولة
**تاريخ آخر تحقق:** 2026-07-14
**النطاق:** إنشاء وثائق `tournamentMemberships` المفقودة لمالك كل بطولة قديمة فقط

---

## 1. ضمانات الترحيل

- يستخدم السكربت معرّفًا ثابتًا بصيغة `organizerId_tournamentId`&rlm;، المطابق لعقد إنشاء البطولة الحالي في `TournamentRepositoryImpl`&rlm;.
- ينشئ فقط الوثيقة الغائبة داخل معاملة Firestore؛ لا يستبدل وثيقة موجودة ولا يحدّثها.
- يعيد فحص مصدر البطولة داخل المعاملة؛ إذا تغيّر المنظم أو حذفت البطولة يتوقف عن هذه الحالة ويسجلها.
- يكتب الحقول الأربعة المسموح بها فقط: `tournamentId` و`userId` و`role` و`createdAt`&rlm;.
- الوضع الافتراضي معاينة `--dry-run`&rlm;؛ لا تحدث كتابة إلا مع `--apply` صراحة.

## 2. أدلة التنفيذ المحلي

| الدليل | النتيجة |
| :--- | :--- |
| اختبارات Functions | نجح `npm run test:functions` بنتيجة `27 passing`&rlm;، وتشمل اختبارات الترحيل للمعاينة والتنفيذ وإعادة التنفيذ والتعارض والسباق المتزامن |
| فحص JavaScript | نجح `node --check` لملفي الترحيل والـCLI |
| اختبار Firestore Emulator | نجحت معاينة ثم `--apply` ثم إعادة التنفيذ؛ أنشئت عضوية واحدة فقط ثم عُرضت كوثيقة متوافقة في الإعادة |
| واجهة CLI | `--help` يعمل، ويرفض التشغيل بلا `--project` صريح |

## 3. نتيجة المعاينة المستهدفة والحاجز الحالي

نجحت معاينة read-only على <bdi dir="ltr">el7reef-app</bdi> في 2026-07-14 باستخدام جلسة Firebase CLI المخولة ومنطق الترحيل نفسه. فُحصت خمس بطولات؛ الخمس مؤهلة وتحتاج إنشاء عضوية منظّم، مع صفر تعارضات وصفر مصادر تالفة وصفر استخدام لقيمة وقت بديلة. لم تحدث أي كتابة.

لا تُشغَّل صيغة <bdi dir="ltr">--apply</bdi> قبل أخذ backup موثق وتجهيز ADC أو Service Account خارج Git بصلاحيات Firestore اللازمة. قاعدة production لا تملك Point-in-Time Recovery أو حماية حذف مفعلة، لذلك لا تكفي سلامة السكربت وحدها كبديل للنسخة الاحتياطية.

مثيل Firestore المستهدف هو `(default)` من نوع `FIRESTORE_NATIVE` وإصدار `STANDARD` في `nam5`&rlm;. كانت حماية الحذف وPoint-in-Time Recovery معطلتين عند الفحص، لذلك يلزم export/backup موثق قبل أي كتابة إنتاجية.

## 4. ترتيب التشغيل المستهدف

1. يجهز المشغل بيانات اعتماد تطبيق مؤقتة أو جلسة ADC خارج المستودع، ويتحقق من أنها تخص `el7reef-app`&rlm;.
2. يأخذ المشغل export/backup قابلًا للاستعادة، ويسجل وقت البدء ومالك العملية ومكان الدليل خارج Git.
3. يشغل المشغل المعاينة التالية أولًا:

```bash
npm --prefix functions run migration:tournament-memberships -- --project el7reef-app --dry-run
```

4. يراجع المشغل العدادات؛ أي `conflicts` أو `invalidSources` أو `sourceChanged` يوقف العملية حتى تعالج البيانات يدويًا.
5. إذا كانت المعاينة نظيفة، يشغل المشغل التنفيذ مرة واحدة:

```bash
npm --prefix functions run migration:tournament-memberships -- --project el7reef-app --apply
```

6. يعيد المشغل الأمر ذاته مع `--dry-run` أو `--apply` ويتحقق من `created: 0` وزيادة `existingCompatible` فقط.
7. يلحق المشغل مخرجات العدادات ووقت التنفيذ بالوثيقة `08` قبل تحويل `UCP-103` إلى `DONE`&rlm;.

## 5. الرجوع والتعامل مع الفشل

- عند ظهور تعارض أو مصدر غير صالح، لا يحاول السكربت إصلاحه ولا يبدل أي وثيقة؛ يوقف المشغل التنفيذ ويعالج السجل المحدد يدويًا.
- عند فشل عملية `--apply` بعد جزء من الصفحات، يعاد تشغيلها بعد التحقيق؛ المعرّف الثابت و`create` داخل المعاملة يمنعان التكرار والاستبدال.
- عند الحاجة إلى رجوع بعد كتابة مقبولة، يستخدم المشغل الـbackup الموثق وخطة الاستعادة المعتمدة، لا حذفًا جماعيًا مرتجلًا.
